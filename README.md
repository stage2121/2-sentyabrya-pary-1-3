Практическая демонстрация ООП

Данный проект наглядно иллюстрирует три ключевых принципа объектно-ориентированного программирования через реализацию предметных моделей.

Инкапсуляция реализована через:

Защищённые атрибуты (_engine_temperature в классе Car, _coords в Figure), скрывающие внутреннее состояние объектов

Публичные интерфейсы (start_engine(), drive(), move(), change_scale()) для безопасного взаимодействия

Геттеры и сеттеры (get_coords(), set_coords()), обеспечивающие контролируемый доступ к данным

Наследование построено по двум иерархиям:

Базовый класс Figure → специализированные классы Line, Rect, Ellipse, Triangle

Базовый класс Figure → классы площадных фигур Circle и Square с собственными формулами расчёта

Полиморфизм проявляется через:

Единый контракт draw() для всех графических объектов, где каждая фигура реализует свою логику отображения

Общий метод calculate_area() для вычисления площади у разных фигур

Единообразную обработку разнотипных объектов в одном цикле, что демонстрирует гибкость и расширяемость системы

Архитектура спроектирована так, что добавление новых классов (например, новых фигур) не требует изменения существующего кода — достаточно создать дочерний класс, реализующий необходимые методы.

Пример 1: Работа с классом Cat
cat1 = Cat("Дворняга", "Шарик", 5) cat1.draw()

Пример 2: Работа с классом Car
my_car = Car() my_car.start_engine() my_car.drive()

Пример 3: Работа с классом Graph
gr1 = Graph(10, 5, 1.5) gr1.move(4, -2) gr2.change_scale(1.5)

Пример 4: Работа с фигурами (полиморфизм)
figures = [line, rect, ellipse, tria]

task1 - Создание класса Cat. В него добавлены три свойства (атрибута): breed (порода), name (имя) и age (возраст). В программе создаются три разных кота (объекта этого класса) с разными данными, после чего в консоль выводится информация о каждом коте.

task2 - Класс Cat из первой задачи дополняется методом draw(). Этот метод при вызове выводит в консоль сообщение вида: «На экране рисуется кот [Имя], порода [Порода]». Вызов этого метода производится для всех трёх созданных котов.

task3 - Создан класс Car. Внутри него определён «скрытый» атрибут _engine_temperature (температура двигателя, по умолчанию равная 20). Реализованы публичные методы: start_engine() (увеличивает температуру до 90 и выводит «Двигатель прогрет») и drive() (проверяет, что температура >= 90, и выводит «Поехали!»). Предусмотрена попытка обращения к _engine_temperature напрямую извне и вызова drive() без прогрева, чтобы убедиться в защищённости логики.

task4 - Создан класс Graph. Внутри него скрыты внутренние координаты _x, _y и _scale. Реализованы методы move(dx, dy) и change_scale(factor). В программе создаются три объекта Graph. Первый перемещается, у второго изменяется масштаб, а третий остаётся без изменений. Выводится их итоговое состояние.

task5 - Создан базовый класс Figure. В него вынесены общие для всех фигур свойства: coords (кортеж координат), width (ширина) и color (цвет). Это позволяет избежать дублирования кода (нарушения принципа DRY) за счёт вынесения общих данных в «родительский» класс.

task6 - Созданы три дочерних класса: Line, Rect и Ellipse, унаследованные от Figure. В каждый из них добавлены свои уникальные свойства: для Line — length (длина), для Rect — height (высота), для Ellipse — radius (радиус). Создаётся по одному объекту каждого класса, после чего выводятся все их свойства. Таким образом реализовано наследование общих свойств и расширение дочерних классов специфичными для них данными.

task7 - В базовый класс Figure добавлен метод draw(), который просто выводит «Рисуется фигура». Этот метод переопределён в дочерних классах (Line, Rect, Ellipse), чтобы каждый выводил своё специфичное сообщение (например, «Рисуется линия...»). В главной программе создаётся общий список, в который помещаются объекты всех трёх типов, и организуется один цикл for, проходящий по списку и вызывающий draw() для каждого элемента. Здесь на практике проявляется полиморфизм: нет необходимости знать точный тип объекта в списке, достаточно вызвать метод базового класса, а выполняется код нужного дочернего.

task8 - Без изменения кода цикла из Задачи 7 (ни одной строчки!) создаётся новый класс Triangle, унаследованный от Figure, в котором переопределён метод draw(), и объект треугольника добавляется в тот же самый список. После запуска программы становится понятно главное преимущество полиморфизма, описанное в тексте: программа легко расширяется новыми типами без переписывания старой логики (без добавления новых if/else или циклов).

task9 - Создана полноценная мини-система:

Инкапсуляция: Базовый класс Figure скрывает свои координаты. Доступ к ним предусмотрен только через методы get_coords() и set_coords().
Наследование: Созданы классы Circle и Square, унаследованные от Figure.
Полиморфизм: В обоих дочерних классах реализован метод calculate_area(). В главной программе создаётся список из 5 разных фигур (круги и квадраты). В одном цикле вычисляется и выводится общая площадь всех фигур в списке. Таким образом, все три концепции (инкапсуляция, наследование, полиморфизм) объединены в одном рабочем проекте, как описано в заключении текста.
